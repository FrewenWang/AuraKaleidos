第10章：模型量化基础理论

量化，说白了就是给模型“减肥”。

我刚开始接触量化时，觉得这东西挺玄乎。把32位浮点数变成8位整数，精度能不掉？后来踩过坑、调过参，才明白量化其实是工程与理论的完美平衡。今天咱们就把量化的底裤扒干净。

10.1 量化原理：对称 vs 非对称

量化的核心思想很简单：用更少的比特数表示数值。但怎么映射，这里头有讲究。

对称量化，就是让零点对齐到0。公式长这样：

量化值 = round(原始值 / 缩放因子)
反量化值 = 量化值 × 缩放因子

缩放因子 = max(|原始值|) / 127（INT8情况下）。

我做过一个实验：用对称量化处理ReLU后的特征图。结果发现，一半的量化范围都浪费了——因为ReLU输出全是非负数。这就是对称量化的短板。

非对称量化就灵活多了。它引入了零点偏移：

量化值 = round(原始值 / 缩放因子) + 零点
反量化值 = (量化值 - 零点) × 缩放因子

缩放因子 = (max - min) / 255，零点 = round(-min / 缩放因子)。

你看，非对称量化能覆盖任意数值范围。我在项目中处理过一批分布极不均匀的权重，用非对称量化后，精度损失比对称量化少了0.3%。

核心区别一句话：

  • 对称量化：零点固定为0，适合权重分布对称的场景（比如经过BN后的权重）
  • 非对称量化：零点可偏移，适合激活值这种分布不对称的数据

我的经验：卷积层的权重用对称量化，激活值用非对称量化。这是业界主流做法，YOLOv11官方也是这么干的。

10.2 量化精度：INT8 vs FP16

选哪种精度？这得看你的硬件和需求。

精度类型 比特数 表示范围 精度损失 推理加速
FP32 32 ~3.4e38 无 1x
FP16 16 ~6.5e4 极小 ~2x
INT8 8 -128~127 中等 ~4x

FP16，说白了就是半精度浮点。它保留了浮点数的动态范围，只是精度砍了一半。我在NVIDIA Jetson上跑过FP16的YOLOv11，mAP只掉了0.1%，速度却快了1.8倍。嗯，这买卖划算。

INT8就猛了。模型体积直接缩到1/4，推理速度能翻4倍。但代价也明显——精度会掉。我遇到过最惨的一次，INT8量化后mAP掉了5%。后来发现是某个层的激活值分布太广，量化后信息全丢了。

避坑指南：我曾经在边缘设备上直接上INT8，结果模型输出全是噪声。后来才意识到，那个设备不支持INT8指令集，量化后的模型反而被转成了FP32跑，速度没提升，精度还掉了。所以，先查硬件文档！

10.3 量化感知训练 vs 后训练量化

这两种方法，我分别用过不下十次。说说我的感受。

后训练量化（PTQ）：模型训练完后，直接量化。简单粗暴，适合快速部署。

# PyTorch后训练量化示例
import torch
model = torch.load('yolov11.pt')
model.eval()

# 插入量化/反量化节点
model.qconfig = torch.quantization.get_default_qconfig('fbgemm')
model = torch.quantization.prepare(model, inplace=True)
# 跑几批校准数据
model = torch.quantization.convert(model, inplace=True)

PTQ的问题在于：它不知道量化后的误差会怎么影响后续层。我做过对比，PTQ在YOLOv11上mAP掉了1.2%。

量化感知训练（QAT）：在训练过程中模拟量化效果。模型会学会适应量化误差。

# QAT训练流程
model.qconfig = torch.quantization.get_default_qat_qconfig('fbgemm')
model = torch.quantization.prepare_qat(model, inplace=True)
# 正常训练几个epoch
optimizer = torch.optim.SGD(model.parameters(), lr=1e-4)
for epoch in range(5):
    for data, target in train_loader:
        optimizer.zero_grad()
        output = model(data)
        loss = criterion(output, target)
        loss.backward()
        optimizer.step()
# 最后转为量化模型
model = torch.quantization.convert(model, inplace=True)

QAT的效果明显更好。我试过，YOLOv11用QAT后mAP只掉了0.3%。但代价是训练时间多了30%。

我的建议：

  • 项目时间紧、精度要求不高 → 用PTQ
  • 精度敏感、有训练资源 → 用QAT
  • 折中方案：先用PTQ快速验证，如果精度不达标再上QAT

10.5 量化后的精度验证

量化完别急着部署。先跑一遍验证集，看看精度变化。

我一般会关注三个指标：

  • mAP变化：量化后mAP下降超过1%，说明量化策略有问题
  • 单层误差：逐层对比量化前后的输出，找出误差最大的层
  • 极端值：检查量化后的权重有没有出现全0或全127的情况

一个小技巧：我曾经遇到量化后某个检测头输出全0。排查后发现，那层的权重范围是[-0.001, 0.001]，量化后全被映射到了0。解决办法：把那层单独用FP16，其他层用INT8。混合精度量化，有时候比纯INT8效果更好。

量化不是银弹。它适合对延迟敏感、对精度容忍度高的场景。如果你做的是医疗影像、自动驾驶这种精度至上的项目，建议先做大量验证再上量化。

好了，量化理论就聊到这儿。记住：对称量化省范围，非对称量化保精度；PTQ省时间，QAT保精度。具体选哪个，看你的项目需求。
