第十三章：模型导出与格式转换

模型训练完了，剪枝量化也搞定了。嗯，这时候你手里拿着的，其实还是个「半成品」。

为什么这么说？因为PyTorch的模型格式，说白了就是个训练态的容器。它里面装着计算图、梯度信息、优化器状态……一大堆部署时根本用不上的东西。我刚开始做部署时，直接把.pt文件扔到生产环境，结果发现推理速度慢得离谱。后来才明白——你得把它「翻译」成目标平台能读懂的语言。

这一章，我们就来聊聊这个翻译过程。从ONNX开始，再到TensorRT和OpenVINO，每一步我都会把踩过的坑说清楚。

核心逻辑：模型导出不是简单的格式转换，而是针对目标硬件的「性能调优」。同样的网络，导出方式不同，推理速度可能差3-5倍。

1. 导出ONNX格式

ONNX，全称Open Neural Network Exchange。说白了，它就是深度学习模型界的「通用语言」。不管你是用PyTorch、TensorFlow还是其他框架训练的，都能转成ONNX。然后ONNX又能转成各种部署格式。

我个人习惯在剪枝量化完成后，第一时间导出ONNX。为什么？因为ONNX是后续所有优化的基础。你想想看，如果ONNX这一步出了问题，后面TensorRT、OpenVINO全得跟着崩。

导出代码其实很简单，PyTorch官方提供了torch.onnx.export接口。但有几个坑我得提醒你：

我曾经在导出时忘记设置opset_version，结果默认用了老版本，导致TensorRT导入时一堆算子不支持。折腾了两天才发现是版本问题。

import torch
import torch.onnx

# 假设model是你的YOLOv11模型，已经加载了剪枝量化后的权重
model = YOLOv11Model()
model.load_state_dict(torch.load('pruned_quantized_model.pth'))
model.eval()

# 构造一个虚拟输入
dummy_input = torch.randn(1, 3, 640, 640)

# 导出ONNX
torch.onnx.export(
    model,
    dummy_input,
    'yolov11_pruned.onnx',
    export_params=True,
    opset_version=17,  # 我建议用17或以上版本
    do_constant_folding=True,
    input_names=['input'],
    output_names=['output'],
    dynamic_axes={
        'input': {0: 'batch_size'},
        'output': {0: 'batch_size'}
    }
)
print("ONNX导出完成！")

这里有个细节：dynamic_axes参数。如果你部署时batch size是固定的，可以不加。但如果你像我一样需要处理不同batch size的请求，一定要加上。否则导出的ONNX会固定batch size为1，后面改起来很麻烦。

小技巧：导出后可以用onnxruntime跑一遍推理，验证结果是否正确。我每次导出完都会做这个检查，能提前发现80%的问题。

2. ONNX简化与优化

导出的ONNX文件，其实有很多冗余信息。比如一些恒等映射节点、多余的reshape操作。这些在训练时没问题，但部署时就是累赘。

我推荐用onnx-simplifier这个工具。它能把计算图里的冗余节点去掉，让模型更干净。我在项目中遇到过，简化后的ONNX文件体积能缩小30%，推理速度提升10%左右。

# 安装
pip install onnx-simplifier

# 简化
python -m onnxsim yolov11_pruned.onnx yolov11_simplified.onnx

# 验证简化后的模型是否正确
python -m onnxsim yolov11_pruned.onnx yolov11_simplified.onnx --check

除了简化，还有几个优化操作我建议你加上：

  • 常量折叠：把计算图中能提前算好的常量都算好，减少运行时计算量
  • 算子融合：把连续的几个算子合并成一个，减少内存读写
  • 精度校准：如果模型是FP16或INT8的，确保ONNX里的精度设置正确

注意：简化后的模型一定要做精度验证。我见过有些简化工具把关键节点删掉了，导致模型输出完全不对。所以「简化+验证」要成对出现。

3. 导出TensorRT引擎

TensorRT是NVIDIA的推理优化引擎。说白了，它就是专门为NVIDIA GPU量身定做的「加速器」。同样的模型，用TensorRT跑，速度能快2-5倍。

导出TensorRT引擎有两种方式：

  1. 从ONNX直接转：用trtexec命令行工具
  2. 用Python API构建：更灵活，可以自定义优化策略

我个人习惯用第一种，简单直接。但要注意，TensorRT对ONNX的算子支持有限。我遇到过好几次，ONNX里用了某个不常见的算子，TensorRT直接报错不支持。

避坑指南：导出TensorRT引擎前，先用onnx2trt工具检查一下算子兼容性。如果有不支持的算子，需要手动替换或重写。

# 使用trtexec命令行工具
trtexec --onnx=yolov11_simplified.onnx \
        --saveEngine=yolov11_fp16.engine \
        --fp16 \
        --workspace=4096 \
        --minShapes=input:1x3x640x640 \
        --optShapes=input:4x3x640x640 \
        --maxShapes=input:8x3x640x640

# 使用Python API
import tensorrt as trt

logger = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(logger)
network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
parser = trt.OnnxParser(network, logger)

with open('yolov11_simplified.onnx', 'rb') as f:
    parser.parse(f.read())

config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 4 << 30)  # 4GB
config.set_flag(trt.BuilderFlag.FP16)

# 构建引擎
engine = builder.build_serialized_network(network, config)
with open('yolov11_fp16.engine', 'wb') as f:
    f.write(engine)

这里有个关键参数：minShapes、optShapes、maxShapes。它们定义了动态batch的范围。你想想看，如果生产环境里请求量忽高忽低，这个设置就特别重要。我一般把min设为1，opt设为4，max设为16，基本能覆盖大部分场景。

经验之谈：TensorRT的构建时间很长，尤其是大模型。我建议在CI/CD流程里提前构建好引擎，不要等到部署时才构建。另外，不同GPU型号生成的引擎不通用，得针对目标GPU单独构建。

4. 导出OpenVINO格式

OpenVINO是Intel推出的推理优化工具。如果你部署在Intel CPU、集成显卡或VPU上，OpenVINO是首选。

说实话，OpenVINO的导出比TensorRT简单不少。它提供了mo（Model Optimizer）工具，可以直接把ONNX转成OpenVINO的IR格式（Intermediate Representation）。

# 安装OpenVINO
pip install openvino-dev

# 使用Model Optimizer转换
mo --input_model yolov11_simplified.onnx \
   --output_dir ./openvino_model \
   --data_type FP16 \
   --input_shape [1,3,640,640] \
   --mean_values [123.675,116.28,103.53] \
   --scale_values [58.395,58.395,58.395]

转换完成后，会生成两个文件：.xml（网络结构）和.bin（权重参数）。部署时加载这两个文件就行。

我在项目中遇到过一个问题：OpenVINO对某些自定义算子的支持不如TensorRT好。比如YOLOv11里的一些特殊激活函数，OpenVINO可能不支持。这时候需要手动替换成标准算子，或者用OpenVINO的扩展机制注册自定义算子。

对比总结：

特性 TensorRT OpenVINO
目标硬件 NVIDIA GPU Intel CPU/GPU/VPU
推理速度提升 2-5倍 1.5-3倍
算子兼容性 中等 较好
构建时间 较长（分钟级） 较短（秒级）
动态batch支持 支持 有限支持

嗯，到这里，模型导出与格式转换的内容就差不多了。你可能会问：到底选TensorRT还是OpenVINO？我的建议是——看你的部署硬件。有NVIDIA GPU就上TensorRT，用Intel平台就选OpenVINO。如果两者都有，那就都导出，根据实际运行环境动态选择。

最后提醒一句：无论导出哪种格式，一定要做精度验证。我见过太多人导出后直接上线，结果推理结果完全不对。花5分钟验证一下，能省下5小时排查问题的时间。

验证方法：用同一张图片，分别在PyTorch和导出后的引擎上跑一次，对比输出结果的差异。差异在1%以内就算合格。
