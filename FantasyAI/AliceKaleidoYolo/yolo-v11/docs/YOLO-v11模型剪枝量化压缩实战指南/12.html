第12章：量化感知训练实战：插入FakeQuantize节点、模拟量化训练、调整量化参数、模型转换

量化感知训练，简称QAT。说白了，就是在训练过程中假装量化已经发生了。

为什么要这么干？因为直接后训练量化（PTQ）有时候掉精度掉得厉害。我遇到过好几次，模型剪枝完精度还行，一量化直接崩了。后来发现，QAT才是真正能稳住精度的方案。

这一章，我们就把QAT的完整流程走一遍。从插入FakeQuantize节点开始，到模拟量化训练，再到调整参数，最后导出真正的量化模型。

12.1 什么是FakeQuantize？为什么需要它？

FakeQuantize，翻译过来就是“假量化”。它做的事情很简单：

  • 在前向传播时，模拟量化的舍入和截断效果
  • 在反向传播时，使用直通估计器（STE）让梯度能正常回传

你想想看，真正的量化操作是不可导的。如果直接把量化后的整数送进网络，梯度根本传不回去。FakeQuantize就是解决这个矛盾的——它在前向做量化模拟，反向假装没发生过量化。

核心公式：

前向：x_q = clamp(round(x / scale) + zero_point, q_min, q_max)

反向：∂L/∂x ≈ ∂L/∂x_q（STE近似）

我在项目中第一次用QAT时，最困惑的就是这个STE。后来想通了：反正量化误差不大，直接用量化后的梯度近似真实梯度，效果足够好。

12.2 在YOLOv11中插入FakeQuantize节点

YOLOv11的模型结构比较复杂。有卷积、BN、激活、残差连接、SPPF等等。我们不能一股脑全量化，得挑着来。

我个人习惯的做法是：

  • 卷积层和全连接层：必须量化，这是计算主力
  • BN层：一般融合到卷积里再量化，单独量化意义不大
  • 激活层（SiLU/ReLU）：可以量化，但要注意输入输出范围
  • Concat和Add操作：需要特殊处理，因为涉及多路输入

在PyTorch中，插入FakeQuantize节点通常用torch.quantization.QuantStub和DeQuantStub。但YOLOv11这种自定义模型，我建议手动插入torch.quantization.FakeQuantize。

import torch
import torch.nn as nn
from torch.quantization import FakeQuantize, MovingAverageMinMaxObserver

# 定义量化配置
qconfig = torch.quantization.QConfig(
    activation=FakeQuantize.with_args(
        observer=MovingAverageMinMaxObserver,
        quant_min=0,
        quant_max=255,
        dtype=torch.quint8,
        qscheme=torch.per_tensor_affine
    ),
    weight=FakeQuantize.with_args(
        observer=MovingAverageMinMaxObserver,
        quant_min=-128,
        quant_max=127,
        dtype=torch.qint8,
        qscheme=torch.per_tensor_symmetric
    )
)

# 在模型前向中插入FakeQuantize
class QuantizedYOLO(nn.Module):
    def __init__(self, base_model):
        super().__init__()
        self.quant = torch.quantization.QuantStub()
        self.model = base_model
        self.dequant = torch.quantization.DeQuantStub()

    def forward(self, x):
        x = self.quant(x)  # 输入量化
        x = self.model(x)
        x = self.dequant(x)  # 输出反量化
        return x

注意：QuantStub和DeQuantStub只是入口和出口。真正起作用的是模型内部各层绑定的FakeQuantize。你需要用torch.quantization.prepare_qat来递归插入。

12.3 模拟量化训练：该怎么做？

插入完FakeQuantize节点后，模型就可以开始模拟量化训练了。但训练方式和普通训练不太一样。

我总结了几条关键经验：

  • 学习率要调小：一般用原始学习率的1/10到1/5。量化带来的扰动需要更精细的调整
  • 训练轮次不用太多：5-10个epoch就够。QAT本质是微调，不是从头训练
  • 冻结BN层：量化训练时BN的统计量会乱跳，我建议冻结BN或者用较小的momentum
  • 使用校准数据集：不需要全部训练数据，几百张代表性图片就够
# 准备模型
model.qconfig = qconfig
model = torch.quantization.prepare_qat(model, inplace=True)

# 冻结BN（可选）
def freeze_bn(model):
    for module in model.modules():
        if isinstance(module, nn.BatchNorm2d):
            module.eval()
            module.track_running_stats = False

freeze_bn(model)

# 训练循环
optimizer = torch.optim.SGD(model.parameters(), lr=1e-4, momentum=0.9)
for epoch in range(10):
    for images, targets in train_loader:
        outputs = model(images)
        loss = criterion(outputs, targets)
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()
    print(f"Epoch {epoch+1}, Loss: {loss.item():.4f}")

小技巧：训练过程中可以观察FakeQuantize的scale和zero_point变化。如果scale剧烈波动，说明学习率太大了。我曾经遇到过scale直接跳到NaN的情况，后来发现是梯度爆炸，加了梯度裁剪就好了。

12.4 调整量化参数：让精度再高一点

QAT训练完成后，FakeQuantize节点里已经学到了比较好的scale和zero_point。但有时候默认配置不是最优的，我们可以手动调整。

常见的调整手段有：

参数 作用 调整建议
quant_min/quant_max 量化范围 激活用0~255（uint8），权重用-128~127（int8）
observer 统计范围的方法 MovingAverageMinMaxObserver比MinMaxObserver更稳定
qscheme 量化方案 权重用per_tensor_symmetric，激活用per_tensor_affine
averaging_constant 移动平均系数 默认0.01，数据分布稳定时可调大到0.1

我个人习惯的做法是：先用默认配置跑一轮QAT，然后检查每层的量化误差。如果某层误差特别大，就单独调整它的量化参数。

# 查看某层的量化参数
for name, module in model.named_modules():
    if isinstance(module, FakeQuantize):
        print(f"{name}: scale={module.scale}, zero_point={module.zero_point}")

避坑指南：我曾经遇到过一个问题——量化后的模型在推理时精度正常，但部署到边缘设备上就崩了。后来发现是scale和zero_point的精度问题。PC上用的是float32，边缘设备可能只支持float16。解决办法是在导出前把scale转成float16。

12.5 模型转换：从FakeQuantize到真正的量化模型

训练完、调完参，最后一步就是把FakeQuantize模型转换成真正的量化模型。这一步叫“融合”或“转换”。

在PyTorch中，用torch.quantization.convert就能搞定。它会做三件事：

  • 移除FakeQuantize节点
  • 把权重和激活值替换成量化后的整数
  • 插入真正的量化/反量化操作
# 转换模型
model.eval()
model = torch.quantization.convert(model, inplace=True)

# 验证量化模型
with torch.no_grad():
    for images, targets in val_loader:
        outputs = model(images)
        # 计算精度...

# 导出为ONNX（可选）
dummy_input = torch.randn(1, 3, 640, 640)
torch.onnx.export(model, dummy_input, "yolov11_qat.onnx")

重要提醒：convert之前一定要把模型设为eval模式。否则BN层的统计量会重新计算，导致量化参数失效。我刚开始做的时候忘了这步，结果转换后的模型精度直接掉到30%以下，排查了半天才发现。
