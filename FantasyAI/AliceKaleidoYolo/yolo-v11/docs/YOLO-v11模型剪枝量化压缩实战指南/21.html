第二十一章：自动化压缩工具链

说实话，模型压缩这件事，手动做一两次还行。但你要是跟我一样，在项目里要反复调参、对比不同压缩策略、还要适配不同硬件平台……那手动操作真的会让人崩溃。

我最早做YOLOv5剪枝的时候，就是纯手工操作。改一次剪枝率，跑一遍验证，再改，再跑。一个周末就这么搭进去了。后来我学乖了——自动化工具链才是正道。

这一章，我就把常用的几个自动化压缩工具给你捋一遍。NNI、Intel POT、TensorRT Model Optimizer，还有我自己写的自定义脚本。每个工具我都踩过坑，咱们直接说干货。

核心思路：自动化工具链的本质，就是把「剪枝→量化→微调→验证」这个循环，变成一键执行。你只需要定义好策略，剩下的交给工具。

1. NNI：微软的自动压缩工具箱

NNI（Neural Network Intelligence）是我个人用得最多的工具。它最大的好处是——你不用自己写剪枝算法。NNI 内置了十几种剪枝策略，比如 L1 剪枝、FPGM、激活值剪枝等等。

我记得第一次用 NNI 做 YOLOv5 剪枝时，只写了不到 50 行配置代码，就自动跑完了剪枝→微调→评估的完整流程。嗯，当时确实被惊艳到了。

我的习惯：先用 NNI 的自动搜索功能，跑一轮不同剪枝率的组合。它会自动记录每个组合的精度和 FLOPs，你直接挑一个性价比最高的就行。

NNI 的量化模块也值得一提。它支持 QAT（量化感知训练）和 PTQ（后训练量化）。我个人建议：如果时间充裕，用 QAT；如果赶项目，PTQ 就够了。

# NNI 剪枝配置示例（YAML）
experimentName: yolo11_prune
searchSpaceFile: search_space.json
trialCommand: python train.py --prune
trialConcurrency: 2
maxTrialNumber: 20
tuner:
  name: TPE
  classArgs:
    optimize_mode: maximize
trainingService:
  platform: local

注意：NNI 的剪枝结果默认是稀疏权重，不是真正减少参数量。你需要额外调用一次 apply_compression 才能得到真正的轻量模型。我当初就因为这个多花了半天排查问题。

2. Intel POT：OpenVINO 生态的量化利器

如果你最终要部署在 Intel 的 CPU 或 VPU 上，那 Intel POT（Post-training Optimization Tool）就是首选。它专门为 OpenVINO 格式的模型做量化优化。

POT 的工作方式很简单：你给它一个 OpenVINO IR 模型，再给一小部分校准数据，它就能自动完成 INT8 量化。整个过程不需要反向传播，跑得飞快。

我曾经在一个边缘设备项目里，用 POT 把 YOLOv5s 从 FP32 量化到 INT8，推理速度提升了 2.3 倍，mAP 只掉了 0.8%。说实话，这个性价比真的很高。

# POT 量化命令示例
pot \
  --model /path/to/model.xml \
  --weights /path/to/model.bin \
  --engine simplified \
  --data-source /path/to/calibration_data \
  --quantize default \
  --output /path/to/quantized_model

关键点：POT 的校准数据不需要很多，一般 200-500 张图片就够了。但数据分布一定要和真实场景一致，否则量化后的精度会崩。我吃过这个亏。

3. TensorRT Model Optimizer：NVIDIA 的加速引擎

TensorRT Model Optimizer（简称 TRT MO）是 NVIDIA 官方推出的工具。它专门针对 TensorRT 推理引擎做优化，支持 FP16、INT8 量化，以及层融合、内存优化等操作。

TRT MO 的使用流程很清晰：先把 PyTorch 模型导出为 ONNX，然后用 TRT MO 做量化优化，最后生成 TensorRT 引擎文件。整个过程可以写成一个脚本，一键执行。

我建议你在使用 TRT MO 时，重点关注 INT8 量化。因为 FP16 基本是无损的，但 INT8 需要校准数据。TRT MO 支持两种校准方式：熵校准和最小化均方误差校准。我个人更推荐熵校准，效果更稳定。

# TensorRT Model Optimizer 量化示例
import tensorrt as trt
from tensorrt_model_optimizer import ModelOptimizer

optimizer = ModelOptimizer(
    onnx_path="yolo11.onnx",
    precision="int8",
    calibration_cache="calibration.cache",
    calibration_data="calibration_images"
)

optimizer.optimize()
optimizer.save_engine("yolo11_int8.engine")

小技巧：TRT MO 支持动态形状输入。如果你的 YOLOv11 需要处理不同分辨率的图片，记得在配置里开启动态形状支持。否则推理时会报 shape 不匹配的错误。

4. 自定义自动化脚本：灵活才是王道

工具再好，也总有满足不了需求的时候。比如，我想在剪枝后先做一次 PTQ，再做一次 QAT，最后用 TensorRT 做层融合。这种组合操作，现成工具很难一步到位。

所以，我通常会写一套自定义自动化脚本。核心思路是：把每个压缩步骤封装成一个函数，然后用一个主脚本串联起来。

避坑指南：我曾经在自定义脚本里忘了保存中间结果，结果剪枝跑了 8 小时后，量化阶段报错，所有工作白费。所以，一定要在每个步骤后保存 checkpoint。血的教训。

自定义脚本的好处是灵活，但缺点也很明显——你需要自己处理各种异常情况。比如，剪枝后的模型结构变了，量化工具可能不兼容。这时候，你就要在脚本里加入兼容性检查。

5. 工具选型对比

说了这么多，到底该选哪个？我整理了一个对比表，你根据自己情况选就行。

工具 适用场景 剪枝支持 量化支持 自动化程度 我的推荐指数
NNI 通用 PyTorch 模型 强（多种策略） QAT + PTQ 高（自动搜索） ⭐⭐⭐⭐⭐
Intel POT Intel 硬件部署 不支持 PTQ（INT8） 中（需手动配置） ⭐⭐⭐⭐
TensorRT MO NVIDIA GPU 部署 不支持 FP16 + INT8 高（一键优化） ⭐⭐⭐⭐⭐
自定义脚本 特殊需求 / 组合流程 自定义 自定义 完全可控 ⭐⭐⭐（灵活但费时）

我个人建议：如果你刚开始接触自动化压缩，先从 NNI 入手。它文档全、社区活跃，踩坑了也容易找到解决方案。等你对流程熟悉了，再根据部署平台选择 POT 或 TRT MO。

至于自定义脚本，那是进阶玩法。等你用工具解决不了问题时，再考虑自己写。毕竟，我们的目标是快速交付，不是炫技。

最后说一句：自动化工具链不是万能的。它帮你省了重复劳动，但压缩策略的选择、校准数据的准备、精度损失的评估，这些还是得靠你自己。工具是枪，你才是那个扣扳机的人。
