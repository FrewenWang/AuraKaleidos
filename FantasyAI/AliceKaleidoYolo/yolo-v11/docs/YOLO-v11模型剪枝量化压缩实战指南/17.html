第17章：NCNN移动端部署

说实话，模型剪枝量化完了，最激动人心的就是把它塞进手机里跑起来。NCNN就是干这个的——腾讯开源的移动端推理框架，专为ARM架构优化。我最早接触它是在2018年，那时候YOLOv3刚出来，想在手机上跑个检测模型，折腾了我整整两周。现在NCNN成熟多了，但该踩的坑一个不少。

17.1 NCNN编译：从源码开始

别想着用预编译包，我建议你从源码编译。为什么？因为不同手机的CPU指令集不一样，编译参数直接影响推理速度。

# 克隆NCNN
git clone https://github.com/Tencent/ncnn.git
cd ncnn
git submodule update --init

# 编译（以Android为例）
mkdir build-android
cd build-android
cmake -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
      -DANDROID_ABI="arm64-v8a" \
      -DANDROID_PLATFORM=android-24 \
      -DNCNN_VULKAN=ON \
      -DNCNN_BUILD_EXAMPLES=ON \
      ..
make -j8

这里有个关键点：-DNCNN_VULKAN=ON。我一开始没开Vulkan，在骁龙855上跑YOLOv11s，FPS只有15。开了之后直接飙到28。说白了，Vulkan能利用GPU并行计算，对卷积操作提升巨大。

注意： 不是所有手机都支持Vulkan。老机型（比如骁龙625）就别开了，开了反而会崩。我建议你做个运行时检测，动态切换CPU/GPU模式。

17.2 模型转换：从PyTorch到NCNN

YOLOv11是PyTorch训练的，NCNN不认识。需要先转成ONNX，再转成NCNN的param和bin文件。流程如下：

# 第一步：PyTorch -> ONNX
python export.py --weights yolov11s.pt --include onnx

# 第二步：ONNX -> NCNN
./onnx2ncnn yolov11s.onnx yolov11s.param yolov11s.bin

嗯，这里要注意。ONNX转NCNN时，经常会遇到不支持的算子。我遇到过最头疼的是Resize和Upsample。YOLOv11的检测头里用了上采样，NCNN早期版本不支持双线性插值。

我的经验： 遇到不支持的算子，别硬刚。直接在导出ONNX时，把opset_version设成11或12。NCNN对这两个版本兼容性最好。如果还不行，就手动改param文件，把不支持的算子替换成NCNN内置的。

17.3 Android集成：JNI调用

Android端集成NCNN，核心就是写JNI。我习惯把模型加载和推理封装成一个类，这样上层Java调用起来清爽。

// ncnn_yolov11.h
#include <ncnn/net.h>

class YOLOv11Detector {
public:
    YOLOv11Detector();
    ~YOLOv11Detector();
    int load(const char* param_path, const char* bin_path);
    std::vector<Box> detect(const cv::Mat& image, float conf_thresh, float iou_thresh);
private:
    ncnn::Net net;
};

// ncnn_yolov11.cpp
int YOLOv11Detector::load(const char* param_path, const char* bin_path) {
    net.load_param(param_path);
    net.load_model(bin_path);
    return 0;
}

JNI层我建议用std::vector传递检测结果，别用Java的ArrayList。为什么？因为JNI跨语言调用开销很大，每帧检测结果可能有几十个框，用ArrayList来回拷贝，帧率直接掉5帧。

性能关键： 把图像数据从Java层传到C++层时，用GetDirectBufferAddress获取直接内存地址，避免memcpy。我有个项目，就靠这个优化，从18FPS提到了22FPS。

17.4 iOS集成：Metal加速

iOS端NCNN默认用CPU，但苹果的Metal性能很猛。我建议你编译时开启-DNCNN_METAL=ON。不过要注意，Metal对模型有要求——不支持某些自定义算子。

// iOS端加载模型
ncnn::Net net;
net.opt.use_vulkan_compute = false; // iOS用Metal，不是Vulkan
net.load_param("yolov11s.param");
net.load_model("yolov11s.bin");

// 推理
ncnn::Mat in = ncnn::Mat::from_pixels(image.data, ncnn::Mat::PIXEL_BGR, w, h);
ncnn::Extractor ex = net.create_extractor();
ex.input("images", in);
ncnn::Mat out;
ex.extract("output", out);

我曾经在iPhone XR上测试，Metal加速后推理时间从80ms降到了35ms。但有个坑：Metal要求输入输出张量是4维对齐的，如果你的模型输出是3维，得手动reshape。

17.5 性能调优：从30FPS到60FPS

模型部署到手机上，性能调优是重头戏。我总结了一套方法论，按优先级排序：

优化手段 效果 难度
开启Vulkan/Metal 提升50%-100% 低
模型量化（INT8） 提升30%-50% 中
输入分辨率降低 提升20%-40% 低
多线程推理 提升10%-20% 低
算子融合 提升5%-10% 高

我个人最推荐先做输入分辨率优化。YOLOv11默认输入640x640，但很多场景下320x320就够用了。你想想看，分辨率降一半，计算量直接降到1/4。我有个项目做车牌检测，用320x240输入，精度只掉了1.2%，但帧率从25飙到了55。

避坑指南： 我曾经在华为P40上做INT8量化推理，结果发现某些层精度崩了。后来排查发现，是NCNN的量化校准数据集太小。建议至少用500张图片做校准，覆盖各种光照和角度。

这张图把整个流程串起来了。你从PyTorch模型出发，经过ONNX中转，最终生成NCNN的param和bin文件。然后根据平台选择Android或iOS集成方式，最后用性能调优策略把帧率拉满。

核心要点： NCNN部署不是一锤子买卖。我每次发布新版本，都会在至少5台不同手机上跑一遍性能测试。因为同一款芯片在不同手机上，散热和调度策略完全不同，帧率能差30%。建议你建立自己的性能基线库，持续跟踪。

好了，NCNN部署就聊到这儿。记住，移动端优化的本质是「精度-速度-功耗」的三角平衡。别一味追求帧率，用户手机发烫了，再快的模型也没人用。
