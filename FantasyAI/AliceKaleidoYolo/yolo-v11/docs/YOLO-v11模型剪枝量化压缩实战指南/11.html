11. YOLOv11后训练量化实战：使用PyTorch量化API、校准数据集准备、量化模型导出、精度评估

模型剪枝完了，参数量下来了，但推理速度可能还没达到你的预期。这时候，量化就该登场了。

说白了，量化就是把模型里那些浮点数（FP32）换成整数（INT8）。你想想看，一个32位的数变成8位，内存占用直接降到四分之一，计算速度也能翻倍。我最早接触量化时觉得这玩意儿很玄乎，后来发现，其实PyTorch早就把工具给你准备好了。

11.1 后训练量化 vs 量化感知训练

先搞清楚一个概念。量化分两种：

  • 后训练量化（PTQ）：模型训练完，直接拿来做量化。不需要重新训练，快，但精度会有损失。
  • 量化感知训练（QAT）：在训练过程中模拟量化效果，让模型学会适应低精度。精度更高，但需要重新训练。

对于YOLOv11这种大模型，我个人习惯先用PTQ试试水。如果精度掉得不多，那就直接用。如果掉得厉害，再考虑QAT。毕竟时间就是金钱，对吧？

核心结论：PTQ适合快速部署，QAT适合精度敏感场景。YOLOv11的PTQ通常能保持95%以上的原始精度。

11.2 校准数据集准备

PTQ需要一个关键步骤——校准。校准的目的是让量化器知道数据的分布范围，从而确定量化的缩放因子和零点。

校准数据集怎么准备？我一般从训练集中随机抽取200-500张图片。注意，不要用验证集做校准，否则精度评估会虚高。我曾经犯过这个错误，结果部署到现场才发现模型表现不对，排查了半天才找到原因。

代码示例：

import torch
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

# 准备校准数据集
calib_transform = transforms.Compose([
    transforms.Resize((640, 640)),
    transforms.ToTensor(),
])

calib_dataset = datasets.ImageFolder(
    root='path/to/train/images',
    transform=calib_transform
)

# 随机抽取300张
indices = torch.randperm(len(calib_dataset))[:300]
calib_subset = torch.utils.data.Subset(calib_dataset, indices)
calib_loader = DataLoader(calib_subset, batch_size=16, shuffle=False)

小技巧：校准数据集最好覆盖各种场景——白天、夜晚、不同角度、不同目标大小。这样量化出来的模型泛化能力更强。

11.3 使用PyTorch量化API

PyTorch从1.8版本开始就提供了完善的量化API。对于YOLOv11这种目标检测模型，我们主要用torch.quantization.quantize_dynamic做动态量化，或者用torch.quantization.prepare + torch.quantization.convert做静态量化。

我个人更推荐静态量化，因为YOLOv11的卷积层占大头，静态量化能把这些层都转成INT8，加速效果更明显。

具体步骤：

  1. 加载训练好的YOLOv11模型
  2. 将模型设置为eval模式
  3. 使用torch.quantization.QuantStub和torch.quantization.DeQuantStub包装模型
  4. 调用torch.quantization.prepare插入量化观察器
  5. 用校准数据集跑一遍前向传播
  6. 调用torch.quantization.convert完成量化

代码示例：

import torch.quantization as quant

# 加载模型
model = torch.load('yolov11_pruned.pth')
model.eval()

# 添加量化/反量化节点
model.qconfig = quant.get_default_qconfig('fbgemm')
model = quant.QuantWrapper(model)

# 准备量化
model_prepared = quant.prepare(model)

# 校准：用校准数据集跑一遍
with torch.no_grad():
    for images, _ in calib_loader:
        model_prepared(images)

# 转换量化模型
model_quantized = quant.convert(model_prepared)

注意：校准过程中，模型必须处于eval模式。如果混入了训练模式，BatchNorm层的统计量会乱掉，量化后的模型精度会崩。我见过有人因为这个原因折腾了两天。

11.4 量化模型导出

量化完成后，我们需要把模型导出成可部署的格式。PyTorch支持两种导出方式：

  • TorchScript：PyTorch原生格式，跨平台支持好
  • ONNX：开放神经网络交换格式，兼容性最强

对于YOLOv11，我建议导出成ONNX格式。因为ONNX可以直接被TensorRT、OpenVINO等推理引擎加载，部署起来更方便。

导出代码：

# 导出为TorchScript
traced_model = torch.jit.trace(model_quantized, torch.randn(1, 3, 640, 640))
traced_model.save('yolov11_quantized.pt')

# 导出为ONNX
dummy_input = torch.randn(1, 3, 640, 640)
torch.onnx.export(
    model_quantized,
    dummy_input,
    'yolov11_quantized.onnx',
    opset_version=13,
    input_names=['input'],
    output_names=['output']
)

提示：导出ONNX时，opset_version建议用13或更高版本，低版本可能不支持量化操作。

11.5 精度评估

量化完，最关心的问题就是：精度掉了多少？

评估方法很简单：用验证集分别跑原始模型和量化模型，对比mAP（平均精度均值）。

我一般会关注两个指标：

  • mAP@0.5：IOU阈值0.5时的平均精度，对量化不太敏感
  • mAP@0.5:0.95：多个IOU阈值的平均，对量化更敏感

如果mAP@0.5下降不超过2%，mAP@0.5:0.95下降不超过5%，那这个量化就是成功的。

评估代码：

from utils.metrics import compute_map

# 原始模型评估
orig_map = compute_map(model, val_loader)
print(f'原始模型 mAP@0.5: {orig_map:.4f}')

# 量化模型评估
quant_map = compute_map(model_quantized, val_loader)
print(f'量化模型 mAP@0.5: {quant_map:.4f}')

# 精度损失
loss = orig_map - quant_map
print(f'精度损失: {loss:.4f}')

经验之谈：如果精度损失超过预期，可以尝试以下方法：

  • 增加校准数据集规模（从300张增加到1000张）
  • 使用per-channel量化（对卷积层效果更好）
  • 改用量化感知训练（QAT）

11.7 常见问题与避坑

最后，分享几个我在项目中踩过的坑：

  • 校准数据量太少：少于100张时，量化后的模型精度可能崩掉。我建议至少200张。
  • 忘记设置eval模式：校准过程中如果模型处于train模式，BatchNorm层会更新，导致量化后精度异常。
  • ONNX导出失败：某些自定义算子可能不支持量化。解决办法是替换成PyTorch原生算子，或者用TorchScript导出。
  • 精度评估不一致：量化模型在CPU和GPU上的推理结果可能略有差异。评估时最好在目标硬件上跑。

最后一句：量化不是银弹，但它确实是目前最实用的模型加速手段之一。只要校准数据集选得好，精度损失完全可以控制在可接受范围内。
