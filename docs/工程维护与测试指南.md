# 工程维护与测试指南

## 仓库定位

AuraKaleidos 是多语言聚合仓库。一级目录之间没有统一运行时依赖，不能通过一个虚拟环境或
一次编译覆盖所有内容。仓库级自动化负责验证可移植的结构和离线行为；平台 SDK、GPU、设备、
模型和业务服务由对应环境完成分层验收。

## 提交前快速检查

在仓库根目录执行：

```bash
python tools/repository_check.py
python -m unittest discover -s tests -v
git diff --check
```

快速检查无网络副作用，覆盖 18 个一级工程的 README、主要维护文档本地链接、9 个 Node 工程
的 `package.json`/lockfile/test 脚本、Git 子模块声明、失效符号链接、大小写冲突、Windows
非法路径、AliceAutoTest 本地敏感配置是否误提交，以及已跟踪 Notebook 输入单元中的疑似
硬编码凭据。Notebook 输出不参与凭据扫描，避免音频、图像等 base64 数据造成误报。它是
仓库卫生检查，不替代子工程测试。

## Python 工程约定

- 可安装子工程使用 `src/` 布局时，`pyproject.toml` 必须配置 pytest 的 `pythonpath = ["src"]`
  或在测试环境 editable 安装，避免只在作者机器上能导入。
- 重型框架应放入可选依赖组。缺少 Paddle、PyTorch、CUDA 等依赖时，相关测试应明确 skip，
  仍要保留不依赖框架的数据解析、安全检查和纯算法测试。
- 单元测试不得下载模型、启动 GUI、访问真实数据库或写入用户主目录。临时文件使用测试框架
  提供的临时目录。
- Python 代码提交前运行 `ruff check`、`ruff format --check` 和 `compileall`。

## Node 与前端工程约定

- 每个 `package.json` 必须有可离线运行的 `test` 脚本，并同步提交 `package-lock.json`。
- 测试使用本地 HTML/JSON fixture，不抓取真实网站、不连接生产 MongoDB、不发送邮件。
- 聚合仓库不共享 `node_modules`。依赖升级按子工程进行，并同时处理测试、lockfile 和弃用警告。

## 移动端与硬件验收

移动端、CUDA、Jetson、TensorRT、QNN 和 Phoenix/VCam 不能用普通桌面 smoke test 代替：

1. 先在通用 CI 完成结构、纯算法、打包和无设备测试。
2. 在目标 OS/SDK runner 完成编译和平台单测。
3. 在模拟器/真实设备完成启动、权限、IPC、摄像头、模型加载和资源释放测试。
4. 记录 SDK、驱动、设备型号、模型哈希与测试数据版本，避免只记录“本机通过”。

旧 Android/Kotlin 和 Flutter 示例保留历史工具链。升级必须作为独立迁移处理，不应在没有对应
SDK 的机器上批量改版本号并宣称完成兼容。

## CI 覆盖

`.github/workflows/merge-validation.yml` 当前包含：

- Ubuntu 仓库结构检查与校验器自测；
- Ubuntu、macOS、Windows 的离线 Python 测试矩阵；
- Ubuntu 的 C++、CUDA 无工具链配置、Shell 与环境脚本验证；
- Ubuntu 的 9 个 Node 工程和 Maven Java 工程；
- macOS 的 iOS `build-for-testing`。

Android SDK 28/29、旧 JDK、Flutter 1.x、Windows Phoenix 业务环境和 GPU/设备 SDK 不适合混入
通用 runner，需配置专用 runner 后再增加对应 job。

## 仓库卫生与清理

- 不提交 `.env`、`config.local.ini`、账号、token、webhook、数据库地址或用户绝对路径。
- 2026-08-25 清理了两份历史 Notebook 中相同的硬编码 API key。即使 key 已失效，也应立即在
  对应平台撤销并轮换；Git 工作区中的删除不会清除已发布的提交历史，必要时还应评估历史重写。
- 不提交 `node_modules`、虚拟环境、`build/`、DerivedData、测试缓存、日志、模型、数据集和视频。
- 子模块使用 `git submodule update --init --recursive` 初始化；不要把缺失子模块替换成空目录。
- 构建后先用 `git status --short` 复核生成物，再删除明确的临时构建目录。
- 新增一级工程时同步更新根 README、`TOP_LEVEL_PROJECTS`、CI 和本测试矩阵。
