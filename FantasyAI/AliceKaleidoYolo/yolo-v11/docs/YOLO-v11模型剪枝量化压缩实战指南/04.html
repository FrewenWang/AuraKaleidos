第4章：模型剪枝基础理论

剪枝，说白了就是给神经网络「瘦身」。

我刚开始接触剪枝时，总觉得这玩意儿挺玄乎——把网络里的参数砍掉一部分，模型还能正常工作？后来亲手做过几个项目才明白，深度学习模型里其实有大量冗余参数。就像你电脑里装了100个软件，真正每天用的可能就20个，剩下的都是占地方。

4.1 剪枝的分类：结构化 vs 非结构化

剪枝的分类，核心就两个方向：结构化剪枝和非结构化剪枝。这两者的区别，我习惯用一个比喻来解释。

非结构化剪枝，就像你从一堆沙子里挑出几粒扔掉。它针对的是单个权重参数。哪些权重绝对值小，就认为它不重要，直接置零。这样做的好处是精度损失小，但坏处也很明显——稀疏后的权重矩阵不规则，硬件加速困难。我在项目中试过，非结构化剪枝后模型体积确实小了，但推理速度几乎没变，因为CPU和GPU对稀疏矩阵的计算支持并不友好。

结构化剪枝，则是直接砍掉整个「模块」。比如扔掉一个卷积核、一个通道，甚至一整层。这样做损失更大，但剪完后模型结构规整，可以直接用现有框架加速。我个人更偏爱结构化剪枝，尤其是在移动端部署时，效果立竿见影。

核心区别总结：

  • 非结构化：细粒度、精度高、硬件不友好
  • 结构化：粗粒度、精度损失大、硬件友好

我的经验：如果你做学术研究，非结构化剪枝更容易发论文。但如果你做工程落地，我建议直接上结构化剪枝。我曾经在一个安防项目里，用结构化剪枝把YOLOv5的模型体积压缩了4倍，推理速度提升了2.3倍，精度只掉了0.8%。甲方很满意。

4.2 剪枝粒度：从细到粗的四个层次

剪枝粒度，说白了就是「你一次砍多大一块」。我把它分成四个层次，从细到粗依次是：

  1. 细粒度剪枝（Fine-grained）：针对单个权重。这是最细的粒度，灵活性最高，但稀疏矩阵存储和计算效率低。
  2. 向量级剪枝（Vector-level）：针对权重矩阵中的一行或一列。比细粒度粗一点，但依然不够规整。
  3. 核级剪枝（Kernel-level）：针对单个卷积核。一个卷积核就是一个3x3或5x5的矩阵，砍掉一个核，就少了一个特征提取器。
  4. 通道级剪枝（Channel-level）：针对整个通道。这是最粗的粒度，直接砍掉一个通道的所有卷积核。剪完后网络宽度变窄，效果最明显。

你想想看，这四个粒度该怎么选？

我个人习惯是：能通道级就别用细粒度。为什么？因为通道级剪枝后，模型结构完全规整，可以直接用TensorRT或NCNN加速。细粒度剪枝虽然精度高，但部署时你得自己写稀疏矩阵乘法，麻烦得很。

避坑指南：我曾经在一个项目中，为了追求极致压缩率，用了细粒度剪枝。结果模型是变小了，但推理速度反而慢了——因为稀疏矩阵在GPU上计算时，访存不连续，导致缓存命中率极低。后来我改成通道级剪枝，虽然压缩率低了一点，但推理速度直接翻倍。

4.3 剪枝评价指标：怎么判断剪得好不好？

剪枝不是瞎砍，得有评价标准。我常用的指标有三个：

指标 含义 我的用法
压缩率 剪枝后参数量 / 原始参数量 一般控制在30%-70%之间，太低没效果，太高精度崩
加速比 剪枝后推理速度 / 原始推理速度 这个才是硬指标，压缩率再高，跑不快也没用
精度损失 剪枝后mAP / 原始mAP 我一般要求损失不超过1%，超过就得调整策略

这三个指标要综合看。举个例子：你压缩率做到90%，但精度掉了5%，那这模型基本废了。反过来，压缩率只有20%，但精度没掉，推理速度也没提升，那剪了个寂寞。

我的经验公式：剪枝效果 = 加速比 × (1 - 精度损失)。如果这个值大于1，说明剪枝是赚的。小于1，说明得不偿失。
