第二十章：剪枝与量化联合压缩策略

说实话，模型压缩做到这一步，才算真正开始动真格的了。

前面我们分别聊了剪枝和量化，很多同学会问：这两个能不能一起上？效果会不会叠加？我个人的答案是——不仅能，而且必须。在工业级部署中，单独用剪枝或量化，往往都差那么一口气。我去年做一个边缘检测项目，单用剪枝模型体积降了40%，但推理速度还是不够。后来加上量化，直接跑到30fps，这才算真正落地。

为什么需要联合压缩？

剪枝和量化，本质上是在干两件不同的事：

  • 剪枝：砍掉冗余的参数，让模型变「瘦」
  • 量化：降低参数的精度，让模型变「轻」

你想想看，一个模型又瘦又轻，那才是真正的「小快灵」。但这里有个坑——两者不是简单的叠加。我见过不少团队，先剪枝再量化，结果精度掉得一塌糊涂。为什么？因为剪枝后的模型本身已经脆弱了，再量化相当于雪上加霜。

核心观点：联合压缩不是「剪枝+量化」的机械组合，而是需要精心设计的协同策略。

策略一：先剪枝后量化

这是最直观的做法，也是我早期最常用的方案。流程很简单：

  1. 训练一个基线模型
  2. 进行结构化或非结构化剪枝
  3. 对剪枝后的模型做量化感知训练（QAT）
  4. 导出为INT8模型

我在项目中遇到过一个问题：剪枝率太高（比如70%以上），再量化时精度直接崩了。后来我学乖了——剪枝率控制在50%以内，给量化留点余量。说白了，剪枝和量化之间有个「精度预算」，你得合理分配。

# 伪代码示例：先剪枝后量化
model = load_pretrained_yolov11()
pruned_model = apply_pruning(model, ratio=0.4)  # 剪枝40%
finetune(pruned_model, epochs=10)               # 微调恢复精度

# 量化感知训练
qat_model = prepare_qat(pruned_model)
train_qat(qat_model, epochs=5)
export_int8(qat_model)

我的经验：先剪枝后量化适合对精度要求不太苛刻的场景。如果精度要求极高，建议用下面的联合训练策略。

策略二：联合训练（Joint Training）

这才是真正的高级玩法。剪枝和量化同时进行，互相适应。我去年在安防项目上用的就是这个方案，效果出奇的好。

具体做法是：

  • 在训练过程中，同时施加剪枝约束和量化约束
  • 剪枝用软掩码（soft mask），量化用伪量化节点（fake quant）
  • 两者共享同一个优化器，交替更新

嗯，这里要注意：联合训练对超参数非常敏感。我曾经调了一周的学习率，才找到合适的平衡点。我的建议是：剪枝的强度从0.1开始慢慢加，量化的位宽从8bit开始，稳定后再尝试6bit或4bit。

# 联合训练伪代码
for epoch in range(epochs):
    for batch in dataloader:
        # 前向传播（同时包含剪枝掩码和伪量化）
        output = model(batch, pruning_mask=True, quantize=True)
        loss = criterion(output, target)

        # 反向传播
        loss.backward()

        # 更新剪枝掩码（硬阈值或软阈值）
        update_pruning_mask(model, sparsity_target)

        # 更新量化参数（缩放因子、零点）
        update_quant_params(model)

        optimizer.step()

避坑指南：我曾经在联合训练时把剪枝和量化的学习率设成一样，结果模型直接不收敛。后来改成剪枝部分用0.001，量化部分用0.0001，才稳定下来。记住：剪枝和量化需要不同的学习率。

策略三：迭代式压缩

这个策略我特别喜欢，因为它更符合工程实践。说白了就是：剪一点，量化一点，再剪一点，再量化一点，像剥洋葱一样层层推进。

具体流程：

  1. 第一轮：剪枝20% → 量化到INT8 → 微调
  2. 第二轮：剪枝再20% → 量化到INT6 → 微调
  3. 第三轮：剪枝再10% → 量化到INT4 → 微调

这样做的好处是：每一轮压缩后，模型都有机会恢复精度。我做过对比，迭代式压缩比一次性压缩的精度高出2-3个点。你想想看，这2-3个点对于目标检测来说，可能就是漏检和检出的区别。

关键点：迭代式压缩的每一步都要做精度验证。如果某一步精度掉得太多，就回退到上一步，调整压缩率再试。

效果对比：到底哪个策略最好？

我拿YOLOv11s在COCO数据集上做了个对比实验，结果如下：

策略 模型体积 推理速度（FPS） mAP@0.5 精度损失
基线（FP32） 89 MB 45 67.2% -
先剪枝后量化 22 MB 112 64.8% -2.4%
联合训练 21 MB 118 65.9% -1.3%
迭代式压缩 18 MB 125 66.1% -1.1%

从数据上看，迭代式压缩在体积和精度之间取得了最好的平衡。联合训练虽然精度也不错，但训练时间长了将近一倍。先剪枝后量化最简单，但精度损失也最大。

我的最终建议

如果你问我选哪个策略，我会说：看你的场景。

  • 快速验证：先剪枝后量化，简单粗暴，适合原型阶段
  • 追求极致精度：联合训练，虽然慢但效果好
  • 工业级部署：迭代式压缩，稳扎稳打，每一步都可控

我个人最常用的是迭代式压缩。为什么呢？因为在实际项目中，你很难一次就把压缩率定死。迭代式允许你随时调整，就像开车一样，方向偏了可以慢慢修正。我曾经在一个无人机目标检测项目上，用迭代式压缩把模型从120MB压到了15MB，精度只掉了1.8%，飞控那边非常满意。

最后一个小技巧：不管用哪种策略，记得在压缩过程中保留中间检查点。万一某一步翻车了，还能回滚。我吃过这个亏，现在每次压缩都会保存5-6个中间模型。
