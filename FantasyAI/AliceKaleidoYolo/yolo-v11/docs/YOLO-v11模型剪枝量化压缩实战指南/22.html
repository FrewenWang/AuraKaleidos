第22章 YOLOv11自定义数据集压缩：数据标注格式、数据集划分、训练配置、压缩流程适配

说实话，模型压缩这件事，很多人一上来就调参数、跑脚本，结果发现效果一塌糊涂。我见过太多人栽在数据准备这一步。你想想看，模型压缩的本质是让网络学会「更高效地表达」，如果数据本身就有问题，那压缩出来的模型能好用才怪。

这一章，咱们就聊聊自定义数据集压缩的那些坑。我会把数据标注格式、数据集划分、训练配置、压缩流程适配这几个环节串起来讲。嗯，都是我在项目里踩过的坑，希望能帮你省点时间。

核心观点：数据质量决定了压缩效果的上限。标注不规范，后面所有工作都是白费。

22.1 数据标注格式：别小看这一步

YOLOv11默认用的是YOLO格式的标注。说白了，就是每个图片对应一个同名的txt文件，里面每行代表一个目标。格式长这样：

class_id x_center y_center width height

注意，这里的坐标都是归一化后的值，范围在0到1之间。我刚开始做的时候，就犯过傻——直接把像素坐标写进去了，结果训练出来的模型啥也检测不到。

举个例子，一张640x640的图片，目标中心在(320, 240)，宽高是(100, 80)。那标注应该是：

0 0.5 0.375 0.15625 0.125

计算方式很简单：

  • x_center = 320 / 640 = 0.5
  • y_center = 240 / 640 = 0.375
  • width = 100 / 640 = 0.15625
  • height = 80 / 640 = 0.125

我的习惯：我会用LabelImg或者CVAT来标注，导出时直接选YOLO格式。省得自己手动算坐标，容易出错。

还有一个容易忽略的点——类别编号必须从0开始连续。比如你有3类：人、车、自行车，那编号就是0、1、2。中间不能跳号，否则训练时会报错。我曾经因为删了一个类别没重新编号，排查了半天才发现问题。

22.2 数据集划分：别让验证集变成摆设

数据集划分这事，看着简单，其实门道不少。YOLOv11的训练脚本通常要求你把数据分成三部分：训练集、验证集、测试集。比例我一般用8:1:1。

但这里有个坑——随机划分。你想想看，如果随机分，很可能某个类别的样本全跑到了训练集，验证集里一个都没有。那验证集的mAP算出来虚高，实际部署时直接翻车。

我建议用分层采样。说白了，就是保证每个类别在三个集合里的比例差不多。代码实现也不复杂：

from sklearn.model_selection import train_test_split

# 假设你有图片列表和对应的类别标签
images = [...]  # 图片路径列表
labels = [...]  # 每个图片包含的类别列表（取第一个类别做分层依据）

train_imgs, temp_imgs, train_labels, temp_labels = train_test_split(
    images, labels, test_size=0.2, stratify=labels, random_state=42
)

val_imgs, test_imgs, val_labels, test_labels = train_test_split(
    temp_imgs, temp_labels, test_size=0.5, stratify=temp_labels, random_state=42
)

注意：stratify参数要求标签是离散的。如果你的图片里包含多个类别，可以取主要类别或者随机选一个作为分层依据。虽然不是完美方案，但比纯随机强得多。

划分完之后，目录结构应该是这样的：

dataset/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
├── labels/
│   ├── train/
│   ├── val/
│   └── test/
└── dataset.yaml

22.3 训练配置：压缩前的准备工作

训练配置这块，我直接说重点。YOLOv11的配置文件是YAML格式，你需要关注这几个参数：

参数名 说明 我的建议值
batch 批次大小 16或32，看显存
epochs 训练轮数 300（压缩前）
imgsz 输入图片尺寸 640
optimizer 优化器 SGD（压缩场景更稳）
lr0 初始学习率 0.01

这里有个经验——压缩前的训练，学习率可以稍微大一点。因为我们要让模型充分收敛，后面剪枝量化的时候才有「冗余」可以去掉。如果模型本身就没训练好，剪完直接废了。

dataset.yaml文件的内容大概是这样：

path: /path/to/dataset
train: images/train
val: images/val
test: images/test

nc: 3
names: ['person', 'car', 'bicycle']

避坑指南：path路径最好用绝对路径。我之前用相对路径，换台机器跑就报错，排查了半天才发现是路径问题。

22.4 压缩流程适配：把通用流程嫁接到你的数据上

好了，数据准备好了，训练配置也调好了。接下来就是压缩流程的适配。说白了，就是把前面几章讲的剪枝、量化、蒸馏这些技术，套到你的自定义数据集上。

我画了一张流程图，帮你理清整个流程：

这个流程里，最关键的适配点有两个：

  1. 剪枝率的设定：不同数据集的最佳剪枝率不一样。我一般从0.3开始试，然后0.5、0.7，看mAP下降曲线。如果下降超过5%，就退回到上一个档位。
  2. 量化校准数据：PTQ量化需要一小部分校准数据。我习惯从验证集里随机抽100-200张，覆盖所有类别。太少的话，量化后的精度会崩。

实战经验：我在一个工业检测项目里，数据集只有5000张图片，类别分布极不均匀。剪枝到0.5时mAP掉了8%，但量化后反而只掉了3%。后来发现是剪枝把一些「小目标检测通道」给剪没了。解决办法是——剪枝时保留前几层的通道数，只剪后面的。

22.5 训练脚本适配：改几行代码的事

YOLOv11官方代码其实已经支持自定义数据集了。你只需要改两处：

第一处，是数据加载部分。确保你的数据集路径和标注格式正确：

from ultralytics import YOLO

# 加载预训练模型
model = YOLO('yolo11n.pt')

# 训练自定义数据集
results = model.train(
    data='dataset.yaml',  # 你的配置文件
    epochs=300,
    imgsz=640,
    batch=16,
    device='cuda:0'
)

第二处，是压缩后的微调。剪枝或量化后，需要重新训练几个epoch来恢复精度：

# 剪枝后的模型
pruned_model = YOLO('path/to/pruned_model.pt')

# 微调
results = pruned_model.train(
    data='dataset.yaml',
    epochs=50,  # 微调不需要太多轮数
    lr0=0.001,  # 学习率要调小
    resume=False
)

我的习惯：微调时我会把学习率降到原来的1/10。因为模型已经收敛过了，学习率太大容易把权重「冲散」。

22.6 常见问题与避坑

最后，我总结几个我在自定义数据集压缩时遇到过的坑：

  • 标注文件缺失：有些图片没有目标，但YOLO要求每个图片都有对应的txt文件。空文件也要放一个，否则训练会报错。
  • 类别名称不一致：dataset.yaml里的names顺序必须和标注文件里的class_id一一对应。我见过有人把顺序搞反了，结果模型把「人」识别成了「车」。
  • 图片尺寸不统一：虽然YOLOv11会自动resize，但如果图片长宽比差异太大，压缩后的模型容易在小目标上翻车。我建议训练前先统计一下图片尺寸分布，把特别离谱的筛掉。

曾经有一次：我帮客户压缩一个交通监控模型，数据集里全是白天场景。压缩后部署到晚上场景，mAP直接掉了20%。后来才发现是数据分布和部署场景不匹配。所以，压缩前一定要确认你的验证集能代表真实场景。
