# AURA 多环境开发框架 - 架构设计

## 系统架构

AURA 是一个灵活的多环境开发工具包，支持多个开发环境（dev、mi 等），完整的配置继承和平台特定的覆盖。

## 4层架构

系统对 bash 配置和 bin 工具都使用 4层配置架构：

### Bash 配置层

1. **第1层 - 基础配置**
   - `bash/base/bashrc.fwf`
   - 通用别名、变量和工具
   - 所有环境都会加载

2. **第2层 - 平台特定基础**
   - `bash/base/bashrc_{Linux|Darwin}.fwf`
   - 平台特定的工具（open 等）
   - 仅当文件存在时加载

3. **第3层 - 环境特定**
   - `bash/{env}/bashrc.fwf`（dev、mi 等）
   - 环境特定的别名和变量
   - 仅为选中的环境加载

4. **第4层 - 环境 + 平台**
   - `bash/{env}/bashrc_{Linux|Darwin}.fwf`
   - 环境 + 平台特定配置
   - 覆盖之前的所有层

### 二进制/脚本层

1. **第1层 - 基础工具**（`bin/base/`）
   - 60+ 个通用脚本和工具

2. **第2层 - 平台工具**（`bin/base/{Linux|Darwin}/`）
   - 平台特定的二进制文件（adb、git、ndk 等）

3. **第3层 - 环境工具**（`bin/{env}/`）
   - 环境特定的脚本

4. **第4层 - 环境 + 平台工具**（`bin/{env}/{Linux|Darwin}/`）
   - 环境 + 平台特定的工具

## 配置优先级

### Bash 配置（后面的层覆盖前面的层）
```
第1层 → 第2层 → 第3层 → 第4层
(基础) → (平台) → (环境) → (环境+平台)
```

### PATH 搜索顺序（第一个匹配的胜出）
```
bin/{env}/{Platform}
→ bin/{env}/
→ bin/base/{Platform}/
→ bin/base/
→ bin/main/
→ 系统 PATH
```

## 工作原理

### 1. 环境检测
- 用户通过 `aura-env select <env>` 选择环境
- 选择保存到 `~/.aura-env-config`
- 配置可以来自：`config/environments.conf`、`bash/{env}/` 或 `bin/{env}/`

### 2. 配置加载
当 `aura-dev-env.sh` 被 source 时：
1. 加载 `bash/base/bashrc.fwf`（总是）
2. 加载 `bash/base/bashrc_{Platform}.fwf`（如果存在）
3. 加载 `bash/{SELECTED_ENV}/bashrc.fwf`（如果存在）
4. 加载 `bash/{SELECTED_ENV}/bashrc_{Platform}.fwf`（如果存在）

### 3. PATH 构建
使用 4层优先级构建 PATH，仅包含存在的目录：
- 跳过缺失的目录（优雅降级）
- 保留顺序并移除重复项
- 保留现有系统 PATH

## 优雅降级

系统支持环境目录的部分或完全缺失：

| 场景 | bash | bin | config | 结果 |
|------|------|-----|--------|------|
| 完整 | ✓ | ✓ | ✓ | 完全定制 |
| 部分（仅bash） | ✓ | ✗ | ✓ | 继承工具 |
| 部分（仅bin） | ✗ | ✓ | ✗ | 继承 bash |
| 仅配置 | ✗ | ✗ | ✓ | 全部继承 |

## 添加新环境

要创建新环境：

```bash
# 1. 创建目录
mkdir -p bash/{env_name}/{Linux,Darwin} bin/{env_name}/{Linux,Darwin}

# 2. 添加到配置
echo "env_name" >> config/environments.conf

# 3. 添加配置文件
cp bash/dev/bashrc.fwf bash/{env_name}/bashrc.fwf
# 根据需要编辑...

# 4. 添加工具
cp bin/dev/Linux/* bin/{env_name}/Linux/
# 根据需要编辑...

# 5. 使用
aura-env select {env_name}
source ~/.bashrc
```

## 核心工具

- **aura-env** - 环境管理器
  - `aura-env list` - 列出所有环境
  - `aura-env current` - 显示当前环境
  - `aura-env select <env>` - 切换环境
  - `aura-env show [env]` - 显示配置
  - `aura-env validate [env]` - 验证设置
  - `aura-env info [env]` - 显示环境信息

- **setup.sh** - 初始安装脚本
  - 自动检测 OS 和 shell
  - 更新 ~/.bashrc 或 ~/.zshrc
  - 创建备份
  - 立即可用

- **scripts/init-shell.sh** - 安全初始化
  - 验证必需文件
  - 从错误中恢复

- **scripts/repair-shell-init.sh** - 诊断工具
  - 检查配置
  - 识别问题
  - 建议修复

## 优先级规则

### Bash 配置优先级（后面的覆盖前面的）
1. bash/base/bashrc.fwf
2. bash/base/bashrc_{Platform}.fwf
3. bash/{ENV}/bashrc.fwf
4. bash/{ENV}/bashrc_{Platform}.fwf ← 最高优先级

### Bin PATH 顺序（按搜索顺序）
1. bin/{ENV}/{Platform}/ ← 最先搜索
2. bin/{ENV}/
3. bin/base/{Platform}/
4. bin/base/
5. bin/main/
6. /usr/local/bin:/usr/bin:/bin ← 系统路径

### 同名脚本的处理
如果在多个层都定义了同名脚本，按优先级使用第一个：

```
debug-build 定义在:
  ✅ bin/dev/Linux/debug-build     ← 使用这个
  ❌ bin/dev/debug-build
  ❌ bin/base/Linux/debug-build
  ❌ bin/base/debug-build
```

### 不同脚本的叠加
不同名称的脚本可以同时使用，例如在 mi 环境中：

```bash
$ adb-manager list                (来自 bin/mi/Linux/)
$ ndk-build-helper debug          (来自 bin/mi/Linux/)
$ mi-build                        (来自 bin/mi/)
$ adb devices                     (来自 bin/base/Linux/)
所有命令都可用！
```
