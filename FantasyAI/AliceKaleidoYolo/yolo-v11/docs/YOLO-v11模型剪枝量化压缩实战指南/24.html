第24章：模型压缩安全性与鲁棒性

模型压缩做到最后，你会发现一个扎心的事实：模型变小了，但可能也变“脆”了。

我最早做剪枝时，只盯着精度不掉、推理变快，觉得万事大吉。直到有一次，我把剪枝后的YOLOv5部署到安防摄像头上，结果一张加了轻微噪点的图片，直接让模型把行人识别成了“不明物体”。嗯，从那以后，我再也不敢忽视鲁棒性这回事。

这一章，我们就来聊聊压缩后的模型到底有多“抗揍”。说白了，就是三个维度：对抗攻击、量化噪声、剪枝后遗症。

24.1 对抗攻击：模型压缩后的“照妖镜”

对抗攻击是什么？就是给输入图片加一点点人眼看不出的扰动，让模型输出完全错误的结果。你想想看，自动驾驶里一个“停止”标志被贴了几块小贴纸，模型就当成“限速80”——这可不是开玩笑的。

压缩后的模型，因为参数变少、表征能力下降，往往对这类扰动更敏感。我个人习惯在剪枝前后都跑一遍对抗攻击测试，看看模型是不是“纸老虎”。

24.1.1 快速对抗攻击测试（FGSM）

最简单的攻击方法就是FGSM（Fast Gradient Sign Method）。原理不复杂：沿着梯度方向加一点噪声，让损失函数变大。

import torch
import torch.nn.functional as F

def fgsm_attack(model, images, labels, epsilon=0.03):
    """
    快速梯度符号法攻击
    epsilon: 扰动强度，一般0.01~0.1
    """
    model.eval()
    images.requires_grad = True

    outputs = model(images)
    loss = F.cross_entropy(outputs, labels)

    # 反向传播，计算梯度
    model.zero_grad()
    loss.backward()

    # 生成对抗样本
    sign_data = images.grad.sign()
    perturbed_images = images + epsilon * sign_data

    # 裁剪到有效像素范围
    perturbed_images = torch.clamp(perturbed_images, 0, 1)

    return perturbed_images

# 测试剪枝前后的鲁棒性
def evaluate_robustness(model, dataloader, epsilon=0.03):
    correct = 0
    total = 0

    for images, labels in dataloader:
        perturbed = fgsm_attack(model, images, labels, epsilon)
        outputs = model(perturbed)
        _, predicted = torch.max(outputs.data, 1)
        total += labels.size(0)
        correct += (predicted == labels).sum().item()

    return 100 * correct / total

# 对比测试
print(f"原始模型对抗鲁棒性: {evaluate_robustness(original_model, test_loader):.2f}%")
print(f"剪枝后模型对抗鲁棒性: {evaluate_robustness(pruned_model, test_loader):.2f}%")
⚠️ 避坑指南
我曾经遇到过剪枝后模型精度掉了不到1%，但对抗鲁棒性直接腰斩的情况。所以别只看精度，鲁棒性才是部署后的“保命符”。

24.1.2 更强的攻击：PGD

FGSM是一次性攻击，有点“莽”。PGD（Projected Gradient Descent）则是多步迭代，攻击效果更强。我个人做安全评估时，至少会用PGD跑一轮。

def pgd_attack(model, images, labels, epsilon=0.03, alpha=0.01, steps=10):
    """
    PGD攻击：多步迭代，更精准
    """
    perturbed = images.clone().detach()
    perturbed.requires_grad = True

    for _ in range(steps):
        outputs = model(perturbed)
        loss = F.cross_entropy(outputs, labels)

        model.zero_grad()
        loss.backward()

        # 梯度方向更新
        with torch.no_grad():
            perturbed = perturbed + alpha * perturbed.grad.sign()
            # 投影到epsilon球内
            delta = torch.clamp(perturbed - images, -epsilon, epsilon)
            perturbed = torch.clamp(images + delta, 0, 1)

        perturbed.requires_grad = True

    return perturbed.detach()

24.2 量化噪声鲁棒性：小模型怕“抖”

量化，说白了就是把FP32的浮点数变成INT8的整数。这中间会有精度损失，我们叫它“量化噪声”。

为什么量化后的模型更怕噪声？因为数值精度低了，一点点扰动就可能让激活值跳到错误的区间。我做过一个实验：给量化后的YOLOv11输入图片加0.5%的高斯噪声，mAP直接掉了8个点。而原始模型只掉了2个点。

24.2.1 量化噪声模拟测试

在部署前，我建议先模拟一下量化噪声的影响。可以用简单的均匀噪声来近似。

import numpy as np

def simulate_quantization_noise(model, dataloader, noise_level=0.01):
    """
    模拟量化噪声对模型的影响
    noise_level: 噪声强度，一般0.005~0.02
    """
    total_loss = 0
    count = 0

    for images, labels in dataloader:
        # 添加均匀噪声
        noise = torch.rand_like(images) * noise_level
        noisy_images = images + noise
        noisy_images = torch.clamp(noisy_images, 0, 1)

        outputs = model(noisy_images)
        loss = F.cross_entropy(outputs, labels)

        total_loss += loss.item()
        count += 1

    return total_loss / count

# 对比量化前后的噪声敏感度
orig_noise_loss = simulate_quantization_noise(original_model, test_loader)
quant_noise_loss = simulate_quantization_noise(quantized_model, test_loader)
print(f"原始模型噪声损失: {orig_noise_loss:.4f}")
print(f"量化模型噪声损失: {quant_noise_loss:.4f}")
💡 我的经验
如果量化后模型对噪声的敏感度增加了3倍以上，我建议你考虑量化感知训练（QAT）。它能让模型在训练时就“习惯”量化噪声，部署后更稳定。

24.3 剪枝后鲁棒性评估：别只看mAP

剪枝后的模型，mAP可能只掉了0.5%，但鲁棒性可能已经千疮百孔。我总结了一套“鲁棒性体检”流程，每次剪枝完必做。

24.3.1 多维鲁棒性评估指标

评估维度 测试方法 可接受下降 严重警告线
对抗鲁棒性 FGSM/PGD攻击 < 5% > 15%
噪声鲁棒性 高斯/均匀噪声 < 3% > 10%
光照变化 亮度/对比度调整 < 2% > 8%
遮挡鲁棒性 随机遮挡块 < 4% > 12%

24.3.2 完整的鲁棒性评估代码

def comprehensive_robustness_eval(model, dataloader):
    """
    全面的鲁棒性评估
    """
    results = {}

    # 1. 基线精度
    results['baseline'] = evaluate_accuracy(model, dataloader)

    # 2. 对抗攻击测试
    results['fgsm_0.03'] = evaluate_robustness(model, dataloader, epsilon=0.03)
    results['pgd_0.03'] = evaluate_pgd_robustness(model, dataloader)

    # 3. 噪声测试
    results['gaussian_noise'] = evaluate_noise_robustness(model, dataloader, 'gaussian')
    results['uniform_noise'] = evaluate_noise_robustness(model, dataloader, 'uniform')

    # 4. 光照变化
    results['brightness_+20%'] = evaluate_brightness(model, dataloader, factor=1.2)
    results['brightness_-20%'] = evaluate_brightness(model, dataloader, factor=0.8)

    # 5. 遮挡测试
    results['occlusion_10%'] = evaluate_occlusion(model, dataloader, ratio=0.1)
    results['occlusion_20%'] = evaluate_occlusion(model, dataloader, ratio=0.2)

orig_results = comprehensive_robustness_eval(original_model, test_loader)
pruned_results = comprehensive_robustness_eval(pruned_model, test_loader)

for key in orig_results:
    diff = pruned_results[key] - orig_results[key]
    status = "✅" if abs(diff) < 3 else ("⚠️" if abs(diff) < 8 else "❌")
    print(f"{status} {key}: 原始={orig_results[key]:.2f}% → 剪枝后={pruned_results[key]:.2f}% (变化={diff:+.2f}%)")
🔑 核心判断标准
我个人认为：
- 如果所有维度下降 < 3%：安全，可以部署
- 如果有1-2个维度下降 3-8%：需要针对性优化
- 如果有维度下降 > 8%：建议回退剪枝比例，或者改用结构化剪枝

24.4 提升鲁棒性的实用技巧

发现问题不是目的，解决问题才是。这里分享几个我踩坑后总结的方法。

24.4.1 对抗训练（Adversarial Training）

在剪枝或量化前，先用对抗样本做数据增强。说白了，就是让模型在训练时就见过“坏蛋”，部署时就不怕了。

def adversarial_training_step(model, images, labels, optimizer, epsilon=0.03):
    """
    对抗训练：每个batch都生成对抗样本再训练
    """
    # 生成对抗样本
    adv_images = fgsm_attack(model, images, labels, epsilon)

    # 混合训练：原始样本 + 对抗样本
    combined_images = torch.cat([images, adv_images], dim=0)
    combined_labels = torch.cat([labels, labels], dim=0)

    # 前向传播
    outputs = model(combined_images)
    loss = F.cross_entropy(outputs, combined_labels)

    # 反向传播
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    return loss.item()

24.4.2 量化感知训练（QAT）

量化感知训练能让模型在训练时模拟量化过程，从而学会抵抗量化噪声。我建议在剪枝后、量化前做这个。

# 使用PyTorch的量化感知训练
import torch.quantization as quant

# 准备模型
model.qconfig = quant.get_default_qat_qconfig('fbgemm')
model_prepared = quant.prepare_qat(model, inplace=False)

# 正常训练
for epoch in range(num_epochs):
    for images, labels in train_loader:
        outputs = model_prepared(images)
        loss = criterion(outputs, labels)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

# 训练完成后，转换为量化模型
model_quantized = quant.convert(model_prepared, inplace=False)
⚠️ 注意
对抗训练会降低模型在干净样本上的精度，一般会掉1-3%。这是“用精度换安全”的权衡。我个人习惯控制在2%以内。
