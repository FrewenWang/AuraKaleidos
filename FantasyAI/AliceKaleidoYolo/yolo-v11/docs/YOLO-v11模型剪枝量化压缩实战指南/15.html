第十五章：TensorRT部署实战

终于到了这一步。模型剪了、量化了，现在要让它真正跑起来。

TensorRT，说白了就是NVIDIA给深度学习模型准备的「加速引擎」。我最早接触它是在一个边缘计算项目里，模型在GPU上跑30ms，换成TensorRT后直接掉到8ms——嗯，当时我就觉得这玩意儿有点东西。

15.1 TensorRT安装：别踩这些坑

安装TensorRT其实不难，但版本匹配是个大问题。我个人习惯用tar包安装，比deb包灵活得多。

版本匹配原则：
  • TensorRT版本必须匹配CUDA版本
  • PyTorch版本也要考虑（ONNX导出时会有算子兼容问题）
  • 我建议用TensorRT 8.6+，对YOLOv11支持更好

安装步骤（以TensorRT 8.6.1 + CUDA 11.8为例）：

# 1. 下载tar包（需要NVIDIA账号）
wget https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/8.6.1/TensorRT-8.6.1.6.Linux.x86_64-gnu.cuda-11.8.tar.gz

# 2. 解压
tar -xzvf TensorRT-8.6.1.6.Linux.x86_64-gnu.cuda-11.8.tar.gz

# 3. 配置环境变量
export TRT_PATH=/path/to/TensorRT-8.6.1.6
export LD_LIBRARY_PATH=$TRT_PATH/lib:$LD_LIBRARY_PATH
export PATH=$TRT_PATH/bin:$PATH

# 4. 安装Python包
pip install $TRT_PATH/python/tensorrt-8.6.1-cp39-none-linux_x86_64.whl

# 5. 验证安装
python -c "import tensorrt as trt; print(trt.__version__)"
避坑指南：我曾经在Ubuntu 20.04上装TensorRT 8.4，结果发现ONNX导出时某些算子不支持。后来换成8.6，问题就解决了。所以，尽量用新版本。

15.2 构建Engine：从ONNX到TensorRT

有了TensorRT，下一步就是把训练好的模型转成Engine。这个过程，说白了就是让TensorRT「理解」你的模型结构，然后做各种优化。

核心流程：

  1. 导出ONNX：从PyTorch导出ONNX模型
  2. 创建Builder：TensorRT的构建器
  3. 解析ONNX：用ONNX解析器读取模型
  4. 配置优化：设置精度、工作空间等
  5. 构建Engine：生成优化后的推理引擎

代码示例：

import tensorrt as trt

# 创建logger和builder
logger = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(logger)

# 创建网络定义（显式batch模式）
network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))

# 创建ONNX解析器
parser = trt.OnnxParser(network, logger)

# 解析ONNX模型
with open("yolov11.onnx", "rb") as f:
    if not parser.parse(f.read()):
        for error in range(parser.num_errors):
            print(parser.get_error(error))
        raise RuntimeError("ONNX解析失败")

# 配置构建选项
config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)  # 1GB工作空间

# 构建Engine
serialized_engine = builder.build_serialized_network(network, config)

# 保存Engine
with open("yolov11.engine", "wb") as f:
    f.write(serialized_engine)
关键点：构建Engine时，工作空间大小直接影响优化效果。我一般设1GB，如果显存够大可以设2GB。太小的话，TensorRT可能做不了某些融合优化。

15.3 动态batch支持：灵活应对不同输入

实际部署中，输入batch大小经常变化。比如视频流处理时，可能一次来1帧，也可能一次来8帧。动态batch就是解决这个问题的。

实现方式：

# 在构建Engine时设置动态shape
profile = builder.create_optimization_profile()

# 设置输入维度范围 [batch, channels, height, width]
# 最小值、最优值、最大值
profile.set_shape("input", (1, 3, 640, 640), (4, 3, 640, 640), (8, 3, 640, 640))

config.add_optimization_profile(profile)

# 构建Engine（同上）
serialized_engine = builder.build_serialized_network(network, config)

推理时动态调整batch：

import pycuda.driver as cuda
import pycuda.autoinit

# 加载Engine
with open("yolov11.engine", "rb") as f:
    runtime = trt.Runtime(logger)
    engine = runtime.deserialize_cuda_engine(f.read())

# 创建执行上下文
context = engine.create_execution_context()

# 动态设置输入shape
input_batch = 4  # 假设这次要处理4张图
context.set_binding_shape(0, (input_batch, 3, 640, 640))

# 分配内存
input_size = input_batch * 3 * 640 * 640 * 4  # float32
output_size = input_batch * 84 * 8400 * 4  # YOLOv11输出格式

d_input = cuda.mem_alloc(input_size)
d_output = cuda.mem_alloc(output_size)

# 执行推理
cuda.memcpy_htod(d_input, input_data)
context.execute_v2([int(d_input), int(d_output)])
cuda.memcpy_dtoh(output_data, d_output)
经验之谈：动态batch不是万能的。我遇到过一个问题：batch从1变到8时，推理时间不是线性增长，而是跳跃式增长。后来发现是TensorRT为不同batch大小做了不同优化，但最优值附近的性能最好。所以，如果你知道业务场景的典型batch大小，就把它设成最优值。

15.4 FP16推理：精度与速度的平衡

FP16推理，说白了就是用半精度浮点数代替单精度。速度能翻倍，但精度会略有下降。

开启方式很简单：

# 在构建配置中启用FP16
config.set_flag(trt.BuilderFlag.FP16)

# 构建Engine（同上）
serialized_engine = builder.build_serialized_network(network, config)

FP16对YOLOv11的影响：

指标 FP32 FP16 变化
推理速度 12ms 6ms 提升50%
mAP@0.5 0.723 0.718 下降0.7%
显存占用 1.2GB 0.7GB 减少42%
注意：FP16不是所有层都支持。有些算子（比如某些激活函数）在FP16下会出问题。TensorRT会自动回退到FP32，但性能会打折扣。我建议先跑一遍FP16，看看有没有警告信息。

15.5 INT8推理：极致加速

INT8推理，是TensorRT的终极加速手段。速度能到FP32的4倍，但需要做校准。

校准流程：

  1. 准备校准数据集：从训练集中选500-1000张图
  2. 创建校准器：TensorRT提供多种校准算法
  3. 运行校准：TensorRT会统计每层的激活值分布
  4. 构建INT8 Engine

代码实现：

import tensorrt as trt
import numpy as np
from PIL import Image

class YOLOCalibrator(trt.IInt8EntropyCalibrator2):
    def __init__(self, calibration_files, batch_size=4):
        trt.IInt8EntropyCalibrator2.__init__(self)
        self.calibration_files = calibration_files
        self.batch_size = batch_size
        self.index = 0
        self.device_input = cuda.mem_alloc(batch_size * 3 * 640 * 640 * 4)

    def get_batch_size(self):
        return self.batch_size

    def get_batch(self, names):
        if self.index + self.batch_size > len(self.calibration_files):
            return None

        batch = []
        for i in range(self.batch_size):
            img = Image.open(self.calibration_files[self.index + i])
            img = img.resize((640, 640))
            img = np.array(img, dtype=np.float32) / 255.0
            img = img.transpose(2, 0, 1)  # HWC -> CHW
            batch.append(img)

        batch = np.stack(batch, axis=0)
        cuda.memcpy_htod(self.device_input, batch)
        self.index += self.batch_size
        return [int(self.device_input)]

    def read_calibration_cache(self):
        return None

    def write_calibration_cache(self, cache):
        with open("calibration.cache", "wb") as f:
            f.write(cache)

# 使用校准器
calibrator = YOLOCalibrator(calibration_files, batch_size=4)
config.set_flag(trt.BuilderFlag.INT8)
config.int8_calibrator = calibrator

# 构建Engine
serialized_engine = builder.build_serialized_network(network, config)
INT8校准的关键：
  • 校准数据集要覆盖各种场景（白天、夜晚、不同角度）
  • 我建议用500张图，太少校准不准，太多浪费时间
  • 校准后一定要验证精度，如果mAP下降超过2%，考虑用FP16
