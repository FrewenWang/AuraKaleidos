第十八章：TFLite与CoreML部署

模型训练完了，剪枝量化也搞定了。接下来呢？

说白了，得让模型跑在真实设备上。手机、平板、嵌入式板子，这些才是YOLOv11真正发光发热的地方。我个人习惯把这一步叫做「最后一公里」——前面做得再好，部署不上等于白干。

TFLite转换与量化

TensorFlow Lite，简称TFLite，是Google为移动端和边缘设备准备的推理框架。YOLOv11虽然原生是PyTorch的，但转成TFLite后，在Android设备上跑起来特别顺。

转换流程其实不复杂，核心就三步：

  1. 导出ONNX：从PyTorch导出ONNX格式
  2. ONNX转TFLite：用onnx2tf或直接走TensorFlow路径
  3. 量化：FP16或INT8量化，减小模型体积

我直接给你看代码，这是我项目里用过的转换脚本：

import torch
import onnx
from onnx_tf.backend import prepare
import tensorflow as tf

# 第一步：PyTorch转ONNX
model = torch.load('yolov11_pruned.pt')
model.eval()
dummy_input = torch.randn(1, 3, 640, 640)

torch.onnx.export(
    model,
    dummy_input,
    'yolov11.onnx',
    opset_version=12,
    input_names=['input'],
    output_names=['output']
)

# 第二步：ONNX转TensorFlow
onnx_model = onnx.load('yolov11.onnx')
tf_rep = prepare(onnx_model)
tf_rep.export_graph('yolov11_saved_model')

# 第三步：TFLite转换 + INT8量化
converter = tf.lite.TFLiteConverter.from_saved_model('yolov11_saved_model')
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.target_spec.supported_types = [tf.float16]
# 如果想用INT8，需要提供代表数据集
# converter.representative_dataset = representative_dataset

tflite_model = converter.convert()
with open('yolov11_int8.tflite', 'wb') as f:
    f.write(tflite_model)
注意：INT8量化需要提供代表数据集（representative dataset）。我曾经偷懒随便传了几张图，结果模型精度掉了8个点，后来老老实实准备了200张验证集图片才稳住。

量化方式怎么选？我整理了个表格，方便你对比：

量化类型 模型体积 推理速度 精度损失 适用场景
FP32（无量化） 100% 基准 无 服务器端
FP16 ~50% 快1.5-2倍 几乎无 高端手机、iPad
INT8 ~25% 快3-4倍 1-3% 中低端手机、嵌入式

嗯，这里要注意。INT8量化虽然香，但YOLOv11的某些层对量化特别敏感。我建议你先跑FP16，确认没问题再上INT8。

CoreML模型转换

苹果生态嘛，就得用CoreML。说实话，CoreML的转换比TFLite要顺滑一些，苹果的工具链做得挺完善。

核心工具是coremltools。直接从PyTorch模型转，或者从ONNX转，都行。我个人更推荐从ONNX转，因为中间可以做一些算子优化。

import coremltools as ct
import torch
import onnx

# 方式一：从PyTorch直接转
model = torch.load('yolov11_pruned.pt')
model.eval()

example_input = torch.randn(1, 3, 640, 640)
traced_model = torch.jit.trace(model, example_input)

mlmodel = ct.convert(
    traced_model,
    inputs=[ct.TensorType(shape=(1, 3, 640, 640))],
    convert_to='mlprogram'  # 推荐使用mlprogram格式
)

# 方式二：从ONNX转（我常用这个）
mlmodel = ct.convert(
    'yolov11.onnx',
    convert_to='mlprogram',
    minimum_deployment_target=ct.target.iOS15
)

mlmodel.save('yolov11.mlpackage')
小技巧：CoreML支持mlprogram和neuralnetwork两种格式。mlprogram是苹果主推的新格式，支持更多算子，而且可以针对Apple Neural Engine做优化。我建议你直接用mlprogram。

转换过程中，最常遇到的问题是算子不支持。YOLOv11里有些自定义算子，比如Focus层、某些激活函数。怎么办？

两个思路：要么在导出ONNX时把这些算子替换成标准算子，要么在CoreML转换时手动添加自定义层。我个人更倾向第一种，省事。

边缘设备适配

模型转换完了，还得适配具体设备。不同设备的算力、内存、NPU支持都不一样。

我画了个流程图，帮你理清整个部署决策逻辑：

你看，决策点其实就两个：平台和精度要求。Android走TFLite，iOS走CoreML，这个没得选。

适配过程中，有几个坑我踩过，分享给你：

  • 输入尺寸：边缘设备上640x640可能太大。我试过把输入降到416x416，速度提升明显，但mAP掉了约2%。如果目标是小物体检测，不建议降太多。
  • NMS后处理：TFLite和CoreML都不原生支持NMS。你得在应用层自己实现，或者用各自框架提供的NMS扩展。CoreML有个NonMaximumSuppression层，可以直接加到模型里。
  • 内存占用：YOLOv11的参数量虽然不大，但特征图占内存。在内存只有2GB的设备上，我遇到过OOM。解决办法是减少batch size，或者用更浅的backbone。
核心要点：部署不是简单的格式转换。你得考虑设备算力、内存、NPU支持、甚至散热。我建议你在目标设备上做一次完整的压力测试，跑个1000帧看看会不会降频。

最后说一句，TFLite和CoreML都在快速迭代。苹果每年WWDC都会更新CoreML，Google也在持续优化TFLite的XNNPACK后端。保持关注，及时更新工具链，能让你的模型跑得更快。

我的习惯：每次部署前，我都会在三个设备上测试：一台旗舰机、一台中端机、一台低端机。这样能全面了解模型在不同硬件上的表现。别只盯着最好的设备测，用户手里的机器五花八门。
