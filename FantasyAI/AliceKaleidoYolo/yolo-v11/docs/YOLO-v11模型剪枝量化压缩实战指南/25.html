第二十五章：边缘设备部署实战

说实话，模型剪枝量化做得再好，最后上不了设备也是白搭。我见过太多团队，在服务器上跑得飞起，一到Jetson Nano上就卡成PPT。今天咱们就来聊聊，怎么把压缩后的YOLOv11真正部署到边缘设备上。

我会拿三款主流设备来实战：Jetson Nano、树莓派4B、RK3588。这三兄弟代表了不同的硬件路线，各有各的脾气。你想想看，搞懂了它们，市面上大部分边缘设备你都能搞定。

核心要点：边缘部署不是简单的模型搬运，而是硬件特性、推理框架、模型压缩三者的协同优化。缺一个，性能就上不去。

25.1 设备选型与硬件差异

先说说这三款设备的定位。我个人习惯把它们分成三类：

  • Jetson Nano：带GPU的嵌入式设备，适合跑深度学习推理。算力约472 GFLOPS，功耗5-10W。
  • 树莓派4B：CPU为主的通用计算板，没有GPU加速。算力约13.5 GFLOPS，功耗3-7W。
  • RK3588：带NPU的国产芯片，算力约6 TOPS（INT8）。功耗8-15W，性价比很高。

我在项目中遇到过，有人非要在树莓派上跑原版YOLOv11s，结果帧率只有0.5 FPS。嗯，这其实不是设备的问题，是没选对工具。

25.2 Jetson Nano部署实战

Jetson Nano是我用得最多的设备。它支持TensorRT，这是NVIDIA自家的推理优化引擎。说白了，就是能把你的模型编译成GPU最擅长跑的格式。

25.2.1 环境准备

# 安装JetPack SDK（包含TensorRT、CUDA、cuDNN）
sudo apt update
sudo apt install nvidia-jetpack

# 验证TensorRT版本
dpkg -l | grep TensorRT

# 安装Python依赖
pip install numpy opencv-python pycuda

这里有个坑：JetPack版本要和你的Jetson Nano系统匹配。我曾经因为装了不兼容的版本，折腾了两天才发现是版本问题。

25.2.2 模型转换与部署

我们之前剪枝量化好的模型，是ONNX格式。现在要转成TensorRT的engine文件。

import tensorrt as trt
import torch

# 加载ONNX模型
onnx_model_path = "yolov11_pruned_quantized.onnx"
engine_path = "yolov11.engine"

# 创建TensorRT builder
TRT_LOGGER = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(TRT_LOGGER)
network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
parser = trt.OnnxParser(network, TRT_LOGGER)

# 解析ONNX
with open(onnx_model_path, 'rb') as f:
    parser.parse(f.read())

# 配置优化参数
config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)  # 1GB
config.set_flag(trt.BuilderFlag.FP16)  # 启用FP16推理

# 构建engine
serialized_engine = builder.build_serialized_network(network, config)
with open(engine_path, 'wb') as f:
    f.write(serialized_engine)

print("TensorRT engine 构建完成！")

小技巧：如果显存不够，可以降低workspace大小。我一般设512MB，效果也不错。

25.2.3 推理性能

模型版本 输入尺寸 FP32 FPS FP16 FPS INT8 FPS
YOLOv11n（原版） 640x640 18 32 45
YOLOv11n（剪枝+量化） 640x640 25 48 68
YOLOv11s（剪枝+量化） 640x640 12 22 35

看到了吧？剪枝量化后的模型，在FP16下能跑到48 FPS，基本满足实时检测需求。我实际测试过，在智能安防场景下，这个速度完全够用。

25.3 树莓派部署实战

树莓派没有GPU，所以TensorRT用不了。那怎么办？用ONNX Runtime或者NCNN。我个人更推荐NCNN，它对ARM架构优化得更好。

25.3.1 编译NCNN

# 下载NCNN源码
git clone https://github.com/Tencent/ncnn.git
cd ncnn
mkdir build && cd build

# 编译（启用Vulkan加速，如果有）
cmake -DCMAKE_BUILD_TYPE=Release \
      -DNCNN_VULKAN=ON \
      -DNCNN_BUILD_EXAMPLES=ON ..
make -j4
sudo make install

25.3.2 模型转换

ONNX转NCNN格式，用ncnn自带的工具：

# 将ONNX转成NCNN格式
./tools/onnx/onnx2ncnn yolov11_pruned_quantized.onnx yolov11.param yolov11.bin

# 优化FP16存储（减少模型体积）
./tools/ncnnoptimize yolov11.param yolov11.bin yolov11_opt.param yolov11_opt.bin 1

注意：树莓派的CPU算力有限，建议使用YOLOv11n剪枝后的模型。我试过YOLOv11s，帧率只有3-4 FPS，基本不可用。

25.3.3 推理代码

#include "net.h"
#include "layer.h"

int main() {
    ncnn::Net yolov11;
    yolov11.load_param("yolov11_opt.param");
    yolov11.load_model("yolov11_opt.bin");

    // 设置推理线程数（树莓派4B建议4线程）
    yolov11.opt.num_threads = 4;

    // 读取图像并预处理
    ncnn::Mat in = ncnn::Mat::from_pixels_resize(
        image_data, ncnn::Mat::PIXEL_BGR,
        img_w, img_h, 640, 640
    );

    // 推理
    ncnn::Extractor ex = yolov11.create_extractor();
    ex.input("images", in);
    ncnn::Mat out;
    ex.extract("output", out);

    // 后处理...
    return 0;
}

树莓派上跑剪枝后的YOLOv11n，大概能到8-10 FPS。说实话，不算快，但做简单的目标检测够用了。我曾在智能门禁项目里用过，识别速度能接受。

25.4 RK3588部署实战

RK3588是我最近特别喜欢用的芯片。它自带NPU，INT8算力6 TOPS，价格还便宜。部署流程和前面不太一样，要用瑞芯微自己的RKNN工具链。

25.4.1 环境搭建

# 安装RKNN Toolkit
pip install rknn-toolkit2

# 验证安装
python -c "from rknn.api import RKNN; print('OK')"

25.4.2 模型转换

from rknn.api import RKNN

# 创建RKNN对象
rknn = RKNN(verbose=True)

# 配置量化参数
rknn.config(
    mean_values=[[0, 0, 0]],
    std_values=[[255, 255, 255]],
    target_platform='rk3588',
    quantized_dtype='asymmetric_quantized-8',  # INT8量化
    quantized_algorithm='normal'
)

# 加载ONNX模型
ret = rknn.load_onnx(model='yolov11_pruned_quantized.onnx')
if ret != 0:
    print("加载模型失败！")
    exit(-1)

# 构建RKNN模型
ret = rknn.build(do_quantization=True, dataset='./dataset.txt')
if ret != 0:
    print("构建模型失败！")
    exit(-1)

# 导出RKNN模型
rknn.export_rknn('./yolov11.rknn')

# 释放资源
rknn.release()

经验之谈：RK3588的NPU对INT8量化支持很好。我测试过，剪枝后的YOLOv11n在RK3588上能跑到60+ FPS，比Jetson Nano还快。

25.4.3 性能对比

设备 模型 精度（mAP@0.5） FPS 功耗
Jetson Nano YOLOv11n剪枝+FP16 42.3% 48 8W
树莓派4B YOLOv11n剪枝+INT8 40.1% 9 5W
RK3588 YOLOv11n剪枝+INT8 41.5% 62 10W

从数据上看，RK3588性价比最高。但Jetson Nano生态更成熟，调试工具多。树莓派嘛，适合做原型验证，量产不太推荐。

25.5 部署避坑指南

最后分享几个我踩过的坑：

  • 内存不足：Jetson Nano只有4GB内存，别开太多线程。我一般设2个线程，稳得很。
  • 模型精度下降：INT8量化后mAP掉2-3个点是正常的。如果掉太多，检查校准数据集是否覆盖了所有场景。
  • 推理速度不稳定：树莓派上经常出现忽快忽慢的情况。这是因为CPU频率自动调节。建议锁定CPU频率：sudo cpufreq-set -g performance。
  • NPU驱动问题：RK3588的NPU驱动更新很快。我建议用最新的驱动，老版本有bug。

总结一下：边缘部署没有银弹。Jetson Nano适合GPU加速场景，RK3588适合NPU加速场景，树莓派适合低成本原型。选对设备，用对框架，你的YOLOv11就能在边缘设备上跑得又快又稳。
